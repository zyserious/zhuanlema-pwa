# 排班制计薪模型

> 把「固定工作日 + 固定时段」的时间模型，改成「按日状态表」的时间模型。
> 看起来只改一个函数，实际要改透所有派生计算。

## 两种模型的本质区别

| | 旧模型（原项目假设） | 新模型（排班制） |
|---|---|---|
| 工作日 | `days = [1,2,3,4,5]` 周一到周五 | `shifts['2026-11-14'] = 'd' \| 'n' \| 'x'`，**未排班 = 键不存在** |
| 判断方式 | 看星期几（周期性布尔） | 按日查表（且第三种状态「未排班」是一等公民） |
| 一天多长 | **全局常量** | **随班次变化**：白班 8h、夜班 8h 从 16:00 起算、休息日 0 |

## 为什么这是高危改造

原代码把 `perSecond`（每秒工资）当**全局常量式**的写法扩散到了很多地方。
一旦「一天的长度」随班次变化，**所有消费方都会算错**。

需要逐一改透 7 处派生计算：

1. 今日已挣
2. 每秒工资
3. 下班倒计时
4. 进度节点（25% / 50% / 75% 之类的激励点）
5. 摸鱼计薪
6. 愿望罐进钱速率
7. 预计攒够日期（ETA）

**漏一处就是线上算错钱。** 这类「改一处、漏六处」的隐性耦合，是重构里最容易埋雷的地方。

## 改造清单（换成任何「周期性 → 按日」的需求都适用）

1. **先列出所有「依赖时间长度」的计算点，列全再动手**
2. 把「时间窗」抽成单一函数 `windowOf(date)`，返回当天的起止秒数
   - 夜班 24:00 要归一化成 86400，否则跨零点判断会错
3. 把「今天什么班」抽成 `shiftOf(date)`：**手动排班优先，未排班回退到周内默认**
   - 保留默认值不是为了兼容，是为了「用户还没排班时页面不空」
4. **「未排班」必须能与「休息」区分**
   | 状态 | 提醒 | 统计 | 金额 |
   |---|---|---|---|
   | 未排班 | 不进提醒 | 不进统计 | 走默认工作日 |
   | 休息 | 不进提醒 | 计入休息天数 | 0 |
5. **旧数据迁移要幂等**：老用户存的是 9:00–18:00，需要自动切到 08:00–16:00，但**只能迁一次**（加 `_mig` 标记），否则每次发版都改用户设置
6. **补 UI 让用户能表达新状态**：月历点日期循环 `白 → 夜 → 休 → 未排班 → 白`（四态循环）、整月一键铺、本月班次统计、未排班天数提示

## 核心认知

- **「空值」在业务里往往是一个有意义的状态**。未排班 ≠ 休息，把未填当默认值处理，用户就会收到「你今天要上班」的错误提醒
- **状态机把「未填」作为一等公民，比事后打补丁干净**
- 改时间模型前先问一句：**「一天的长度」是不是被当成常量用了？** 如果是，把所有消费方列全
